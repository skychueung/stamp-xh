# STAMP v0.10 Final Demo Flow

This guide describes the step-by-step demonstration route for STAMP v0.10.

## Prerequisites

- BepiPred3 sidecar running (default: http://localhost:8001)
- PepMLM sidecar running with REAL_MODEL loaded (default: http://localhost:8002)
- STAMP backend running (default: http://localhost:8000)
- Frontend dev server running (default: http://localhost:5173)
- LocalColabFold 1.6.1 available at configured path
- FoldX 5.1 available at configured path

## Demo Steps

### 1. Start BepiPred3 Sidecar

```bash
cd /path/to/bepipred3-sidecar
python -m uvicorn app.main:app --host 0.0.0.0 --port 8001
```

Verify: `curl http://localhost:8001/health`

### 2. Start PepMLM Sidecar (REAL_MODEL)

```bash
cd /path/to/pepmlm-sidecar
python -m uvicorn app.main:app --host 0.0.0.0 --port 8002
```

Verify: `curl http://localhost:8002/health` → should report `model_loaded: true`

### 3. Start STAMP Backend

```bash
cd /path/to/stamp/backend
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

Verify: `curl http://localhost:8000/health`

### 4. Start Frontend

```bash
cd /path/to/stamp/frontend
npm run dev
```

Open browser: `http://localhost:5173`

### 5. Run Integrated Workflow

1. Navigate to **Project Setup** page
2. Enter target protein sequence (or select demo target)
3. Click **"Start Integrated Workflow"**
4. Workflow stages execute automatically:
   - BepiPred3 epitope prediction
   - PepMLM peptide generation
   - LocalColabFold structure prediction
   - pDockQ interface quality calculation
   - FoldX energy quality calculation
5. Monitor progress via **Job Monitor** page

### 6. Open EpitopeScreeningPage

- Navigate to **Epitope Screening** (`/epitope-screening`)
- View predicted epitope candidates
- Inspect BepiPred3 scores and residue ranges
- Verify candidates are persisted in database

### 7. Open ProjectResultsPage

- Navigate to **Project Results** (`/project-results`)
- View generated stamp_candidates
- Inspect structure prediction metrics (mean pLDDT, pTM)
- Inspect interface quality (pDockQ) where available
- Inspect energy quality (FoldX interaction_energy) where available

### 8. Open FinalRankingPage

- Navigate to **Final Ranking** (`/final-ranking`)
- View unified candidate ranking table
- Click any candidate to open **Computational Structure Validation** drawer
- Inside the drawer, verify three panels:
  - **Structure Prediction**: pLDDT, pTM, structure status
  - **Interface Quality**: pDockQ, contact count, interface area
  - **Energy Quality**: FoldX interaction_energy

### 9. Verify Scientific Boundary Labels

- Confirm all candidates display `NOT_EXPERIMENTALLY_VALIDATED`
- Confirm NO MIC / MBC / docking_score / MM-GBSA ΔG values are shown
- Confirm FoldX interaction_energy is labeled correctly (NOT as docking_score)

### 10. Export Candidate Report

- In **ProjectResultsPage** or **FinalRankingPage**, click export buttons:
  - **Export JSON** — structured report with full candidate data
  - **Export Markdown** — human-readable report with scientific boundary section
  - **Export CSV** — spreadsheet-compatible format
- Open exported file and verify:
  - Filename format: `STAMP_candidate_report_{project_id}_{date}.{ext}`
  - Contains explicit scientific boundary statement
  - Contains NO fabricated wet-lab metrics

## Troubleshooting

| Symptom | Likely Cause | Fix |
|---------|-------------|-----|
| "BepiPred3 unavailable" | Sidecar not running | Start sidecar on port 8001 |
| "PepMLM model not loaded" | Sidecar started with stub | Restart sidecar with REAL_MODEL |
| "ColabFold failed" | GPU/conda env issue | Check `/home/xh/kxc/localcolabfold` environment |
| "FoldX failed" | License or path issue | Verify `foldx_20270131` executable path |
| "pDockQ missing" | Complex structure not predicted | Check ColabFold output for errors |
| "Build error" | Missing dependencies | Run `npm install` in frontend directory |

## Notes

- Full end-to-end workflow may take 10–30 minutes depending on sequence length and hardware
- ColabFold requires GPU (tested on RTX 4090)
- FoldX requires valid license file in working directory
- Demo can be shortened by using pre-computed results from an existing project
