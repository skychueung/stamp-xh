# STAMP v0.13 Final Demo Flow

**Stage:** v0.13-final  
**Audience:** Technical reviewers, code auditors  
**Time:** 10 minutes

---

## Objective
Demonstrate that the MMPBSA parser, persistence guard, and frontend Readiness Card correctly enforce scientific boundaries.

---

## Step 1: Parser Test (3 min)

```bash
cd backend
python -m pytest tests/test_mmpbsa_result_parser.py -v
```

**Expected:** 6 tests pass, including:
- `test_official_delta_g_is_null_for_pilot`
- `test_official_delta_g_is_null_for_smoke`

**Show:** Open `backend/tests/fixtures/FINAL_RESULTS_MMPBSA_PILOT.dat` and explain that this is a real pilot artifact, not fabricated.

---

## Step 2: Guard Test (3 min)

```bash
python -m pytest tests/test_mmgbsa_persistence_guard.py -v
```

**Expected:** 11 tests pass, including:
- `test_pilot_result_blocked`
- `test_smoke_result_blocked`
- `test_production_full_criteria_passed`
- `test_production_insufficient_frames_blocked`

**Show:** Open `backend/app/services/mmgbsa_persistence_guard.py` and walk through the production criteria check.

---

## Step 3: Frontend Readiness Card (4 min)

1. Launch backend and frontend:
   ```powershell
   .\start-backend.ps1
   npm run dev
   ```
2. Open http://localhost:5173
3. Navigate to **Peptide Generation**
4. Observe the **MM-GBSA Readiness Card** on the right sidebar:
   - Orange banner: "PILOT_ONLY_NOT_PRODUCTION_MMGBSA"
   - `official ΔG: Not available`
   - Pilot ΔTOTAL shown as "non-production"
   - Warnings listed
   - Scientific boundary footer

**Ask:** "If this were production data, what would change?"
**Answer:** Green banner, actual ΔG value, no warnings, "PRODUCTION_READY" status.
