# STAMP v1.0 Deployment Guide

**Version:** v1.0  
**Date:** 2026-05-12  
**Prerequisites:** Python 3.11+, Node.js 18+

---

## Quick Start

### 1. Backend

```bash
cd backend
python -m venv venv
source venv/bin/activate  # Windows: venv\Scripts\activate
pip install -r requirements.txt
python -c "from app.database import init_db; init_db()"
uvicorn main:app --reload --host 0.0.0.0 --port 8000
```

### 2. Frontend

```bash
npm install
npm run build   # production
npm run dev     # development
```

### 3. Verify

- API docs: http://localhost:8000/docs
- Frontend: http://localhost:5173 (dev) or serve `dist/` (prod)

---

## Environment Variables

Copy `.env.example` to `.env` and configure:

| Variable | Default | Description |
|---|---|---|
| `STAMP_DATABASE_URL` | `sqlite:///./stamp.db` | Database connection |
| `SECRET_KEY` | — | JWT signing key (generate strong random) |
| `CORS_ORIGINS` | `*` | Allowed frontend origins |

---

## Production Checklist

- [ ] Change `SECRET_KEY` to cryptographically secure value
- [ ] Switch SQLite → PostgreSQL
- [ ] Restrict `CORS_ORIGINS` to actual domain
- [ ] Run full test suite: `pytest`
- [ ] Build frontend: `npm run build`
- [ ] Serve `dist/` via nginx or CDN
- [ ] **Never** commit `.env` or API keys

## v1.0-Specific Notes

- MMPBSA parser requires AmberTools for generating `FINAL_RESULTS_MMPBSA.dat`, but the parser itself is pure Python.
- Pilot MM-GBSA results are blocked from production persistence by the guard.
- Frontend build includes `MmgbsaReadinessCard` with scientific boundary banners.
