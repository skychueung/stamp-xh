## 4. Scientific Integrity Boundary

**STRICT RULES enforced across all v0.13 phases:**

1. **Pilot ΔTOTAL is NEVER promoted to official mm_gbsa_delta_g.**
   - Parser sets `official_mm_gbsa_delta_g = null` for all pilot/smoke data.
   - Guard blocks any attempt to persist pilot data with non-null official ΔG.

2. **Production criteria are mandatory.**
   - Trajectory length ≥ 10 ns (configurable, default 10).
   - Frames used ≥ 200 (configurable, default 200).
   - Convergence evidence required (RMSD, RMSF, density, energy drift checks).
   - Only `CONVERGED` or `PARTIAL_CONVERGENCE` status may persist official ΔG.

3. **Frontend clearly distinguishes pilot vs. production.**
   - Pilot: orange banner, "PILOT_ONLY_NOT_PRODUCTION_MMGBSA", "official ΔG: Not available".
   - Production: green banner, "PRODUCTION_READY", actual ΔG value displayed.

4. **Warnings are mandatory for unrealistic values.**
   - Near-zero DELTA TOTAL with zero gas-phase terms triggers explicit warnings.
   - Low frame count triggers explicit warnings.
   - Short trajectory triggers explicit warnings.

5. **No fabricated experimental data.**
   - MMPBSA parser only reads real `.dat` files; no synthetic values injected.
   - All candidates remain `NOT_EXPERIMENTALLY_VALIDATED` unless wet-lab data is entered separately (v0.11).

## 6. Known Limitations

1. **No production MM-GBSA pipeline yet.** Only parser and guard exist; actual production MD + MMPBSA execution is future work (v1.1+).
2. **AmberTools required for `.dat` generation.** Parser is pure Python, but source files require MMPBSA.py from AmberTools.
3. **Pilot data is physically unrealistic.** The 100 ps / 7-frame pilot result validates the parser but is not scientifically meaningful for binding affinity.
4. **No automated convergence diagnostics.** Guard checks metadata (frame count, trajectory length) but does not compute RMSD/RMSF itself.
5. **Frontend card is display-only.** No interactive MMPBSA job submission or real-time monitoring yet.
