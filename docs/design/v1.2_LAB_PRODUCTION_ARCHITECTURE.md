### 1.2 Technology Stack

| Layer | Technology | Rationale |
|---|---|---|
| Frontend | Vite + React + TypeScript | Existing; no change |
| Backend API | FastAPI + Pydantic v2 | Existing; extensible |
| Dev Database | SQLite + SQLAlchemy 2.0 | Existing; sufficient for pilot |
| Prod Database | PostgreSQL-ready schema | Schema designed for migration |
| Job Queue | Redis + RQ (recommended) | Lightweight, Python-native, easy debug |
| Alternative | Celery + Redis/RabbitMQ | If advanced routing needed later |
| File Storage | Local FS (dev) / Server NFS (lab) | Simple, lab-controlled |
| Worker | Python process (RQ Worker) | Runs on server for heavy compute |
| Audit Log | SQLite/PostgreSQL table | Same DB, separate table, append-only |

## 2. Job Queue

### 2.1 Core Data Model

```python
class ComputeJob(Base):
    __tablename__ = "compute_jobs"

    job_id: str          # UUIDv4 primary key
    job_type: str        # enum: see below
    project_id: str      # FK to projects
    candidate_id: str    # FK to stamp_candidates (nullable for batch)
    batch_id: str        # FK to compute_batches (nullable for single)
    status: str          # enum: PENDING, QUEUED, RUNNING, SUCCEEDED, FAILED, RETRYING, CANCELLED, BLOCKED, PARTIAL_SUCCESS
    priority: int        # 0=low, 5=normal, 10=critical
    retry_count: int     # current retry attempt
    max_retries: int     # default 3
    submitted_by: str    # user_id or "system"
    worker_id: str       # hostname + pid of worker
    server_host: str     # "192.168.31.218" or "localhost"
    input_json: dict     # serialized job inputs
    output_json: dict    # serialized job outputs
    error_json: dict     # error classification + traceback
    artifacts_json: dict # list of asset_ids produced
    created_at: datetime
    started_at: datetime | None
    finished_at: datetime | None
```

### 2.2 Job Types

| `job_type` | Description | Typical Runtime |
|---|---|---|
| `colabfold_structure_prediction` | AlphaFold2 multimer prediction | 5–30 min |
| `foldx_energy_quality` | FoldX AnalyseComplex | 1–5 min |
| `flexpepdock_refinement` | Peptide-protein docking | 10–60 min |
| `mmgbsa_production` | Production MM-GBSA (after MD) | 30–120 min |
| `md_production` | 10–50 ns molecular dynamics | 2–24 hours |
| `report_export` | JSON/CSV/XLSX/PDF generation | <1 sec |
| `lims_export` | Push results to LIMS/ELN | 1–10 sec |

### 2.3 Queue Adapter ( abstraction layer )

```python
# app/services/job_queue_adapter.py
class JobQueueAdapter(Protocol):
    def enqueue(self, job_type: str, payload: dict, priority: int = 5) -> str: ...
    def cancel(self, job_id: str) -> bool: ...
    def get_status(self, job_id: str) -> JobStatus: ...
    def retry(self, job_id: str) -> str: ...  # returns new job_id

class RQAdapter(JobQueueAdapter):
    def __init__(self, redis_url: str = "redis://localhost:6379"): ...
```

Using an adapter allows swapping RQ for Celery later without changing business logic.

### 3.1 Data Model

```python
class ComputeBatch(Base):

    batch_id: str           # UUIDv4

    candidate_ids: list[str] # ordered list
    pipeline_stages: list[str] # ["colabfold", "foldx", "flexpepdock", "md", "mmgbsa"]
    status: str             # PENDING, RUNNING, PARTIAL_SUCCESS, SUCCEEDED, FAILED
    created_at: datetime
    completed_at: datetime | None
    summary_json: dict      # success_count, fail_count, retry_count, artifact_manifest
```

### 3.2 Batch → Job Mapping

One batch creates N×M jobs:
- N = number of candidates
- M = number of pipeline stages

Jobs are linked via `batch_id`.

### 3.3 Partial Success & Retry-Failed-Only

```python
def retry_failed_in_batch(batch_id: str) -> list[str]:
    """Create retry jobs only for FAILED jobs in this batch."""
    failed = db.query(ComputeJob).filter_by(batch_id=batch_id, status="FAILED").all()
    new_job_ids = []
    for job in failed:
        if job.retry_count < job.max_retries:
            new_id = queue_adapter.retry(job.job_id)
            new_job_ids.append(new_id)
    return new_job_ids
```

### 5.2 Bundle Export

```python
def create_bundle(batch_id: str) -> FileAsset:
    """Create tar.gz of all assets for a batch."""
    assets = db.query(FileAsset).filter_by(batch_id=batch_id).all()
    bundle_path = f"{storage_root}/bundles/{batch_id}.tar.gz"
    with tarfile.open(bundle_path, "w:gz") as tar:
        for asset in assets:
            tar.add(asset.storage_path, arcname=asset.original_filename)
    return register_asset(bundle_path, file_type="bundle")
```

## 6. Retry and Failure Handling

### 6.1 State Machine

```
PENDING ──► QUEUED ──► RUNNING ──► SUCCEEDED
                              │
                              ▼
                           FAILED ──► RETRYING (if retry_count < max_retries)
                              │            │
                              ▼            ▼
                         CANCELLED    QUEUED (retry re-enqueue)
                              │
                              ▼
                           BLOCKED (dependency failure)
```

### 6.2 Failure Taxonomy

| `error_code` | Meaning | Retryable? |
|---|---|---|
| `ENV_MISSING` | Conda env not found | ✅ Yes (after env creation) |
| `INPUT_INVALID` | Bad PDB/sequence | ❌ No (requires manual fix) |
| `COMPUTE_TIMEOUT` | Exceeded wall time | ✅ Yes (with longer timeout) |
| `CONVERGENCE_FAILED` | MD did not converge | ❌ No (requires parameter change) |
| `DISK_FULL` | No space on server | ✅ Yes (after cleanup) |
| `SERVER_UNREACHABLE` | SSH/network down | ✅ Yes (with backoff) |
| `UNKNOWN_ERROR` | Unclassified | ✅ Yes (1 time) |

## 7. Audit Log

### 7.1 Schema

```python
class AuditLogEntry(Base):
    __tablename__ = "audit_log"

    event_id: str        # UUIDv4
    timestamp: datetime  # UTC
    user_id: str | None
    action: str          # CREATE, UPDATE, DELETE, SUBMIT, CANCEL, RETRY, EXPORT, SYNC, LOGIN, LOGOUT, DENIED
    entity_type: str     # project, candidate, job, batch, asset, report, user
    entity_id: str
    before_state: dict | None
    after_state: dict | None
    ip_address: str | None
    session_id: str | None
```

### 7.2 Key Events to Log

- User submits batch → `action=SUBMIT`, `entity_type=batch`
- Job starts → `action=CREATE`, `entity_type=job`
- Job fails → `action=UPDATE`, `before_state={status: RUNNING}`, `after_state={status: FAILED}`
- Retry triggered → `action=RETRY`, `entity_type=job`
- Result persisted → `action=UPDATE`, `entity_type=candidate`
- Export generated → `action=EXPORT`, `entity_type=report`
- LIMS sync → `action=SYNC`, `entity_type=report`
- Login/logout → `action=LOGIN/LOGOUT`, `entity_type=user`
- Permission denied → `action=DENIED`, `entity_type=user`

## 8. LIMS / ELN API Integration

### 8.1 Connector Config

```python
class LimsConnectorConfig(BaseModel):
    name: str                    # e.g., "labguru", "benchling", "custom"
    base_url: str
    auth_mode: Literal["token", "oauth2", "basic"]

    enabled: bool = False

```

### 8.2 Sync Operations

| Operation | Direction | Endpoint Pattern |
|---|---|---|
| Push candidate metadata | STAMP → LIMS | `POST /api/samples` |
| Push validation report | STAMP → ELN | `POST /api/experiments` |
| Pull assay results | LIMS → STAMP | `GET /api/assays?sample_id={}` |
| Health check | — | `GET /api/health` |

### 8.3 Error Handling

- Network failure → queue for retry with exponential backoff.
- Schema mismatch → log error, queue for manual review.
- Auth failure → alert admin, pause sync.

## 9. Production MD / MM-GBSA

### 9.1 Pre-conditions

Before `official_mm_gbsa_delta_g` may be set:

```python
PRODUCTION_REQUIREMENTS = {
    "run_type": "PRODUCTION",
    "convergence_status": {"CONVERGED", "PARTIAL_CONVERGENCE"},
    "frames_used_min": 200,
    "trajectory_length_ns_min": 10,
    "server_host_required": True,
}
```

### 9.2 Convergence Metrics

| Metric | Threshold | Description |
|---|---|---|
| `sem_kcal_mol` | < 1.0 | Standard error of the mean |
| `std_kcal_mol` | stable | Rolling std dev stable across 4 windows |
| `frames_used` | ≥ 200 | Minimum statistically meaningful sample |
| `trajectory_length_ns` | ≥ 10 | Recommended for reliable ΔG |

### 9.3 Guard Layers (unchanged from v0.13)

1. **Parser:** `official_mm_gbsa_delta_g` is `None` for pilot/smoke runs.
2. **Persistence Guard:** Blocks non-production data from populating official fields.
3. **Frontend Card:** Explicitly labels pilot data as non-ranking.
