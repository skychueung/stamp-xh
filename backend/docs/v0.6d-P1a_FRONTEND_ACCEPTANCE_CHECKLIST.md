### B3 — `cysCount` 在 P1 面板中硬编码为 0

```
// PeptideGenerationPage.tsx line 370:
              <MetricCard label={t.peptideGeneration.cysCount} value={0} />
```

**说明**: 后端 `biocalc.py` 中 `cys_count()` 函数已完整实现，STAMP 候选的 cysteine count 可以通过 `biophysical` 计算得出，但后端当前 `biophysical` 的 `hydrophobicity_fraction` 和 cysteine count 未在 `demo-one` 响应中透传。前端将 Cys Count 硬编码为 `0`。

**影响**: 如果 AMP 序列含 Cys（如某些 β-defensin），显示错误。目前 P4 不含 Cys，暂时无实际影响。
**补救**: 待后端 v0.6d+ 透传 cysteine count 后，改为读取 `candidate.biophysical.cys_count`。
**风险**: 低（当前 P4 序列无 Cys）

---

### B4 — `PPL Score` 在 P1 面板中实际显示 PepMLM 候选名

```
// PeptideGenerationPage.tsx line 372-375:
              <MetricCard
                label={t.peptideGeneration.pplScore}
                value={stampDemo.candidate.targeting_domain.name}
              />
```

**说明**: 标签写的是「PPL」（伪二阶似然），但 value 显示的是 `targeting_domain.name`（如 `OPRF_0029`）。这是命名歧义 — 用户期望看见数值评分，实际显示候选名。

**影响**: UX 迷惑。用户看到 PPL 标签下是 `OPRF_0029` 而非数字。
**补救**: 要么改 label 为「Targeting Peptide Name」，要么从后端 `pepmlm_candidate` 字段透传真实的 PPL 值。
**风险**: 低（视觉歧义，可快速修正）
