## 一、9 项逐条风险复核

### R1 — 前端生产环境是否还会请求 127.0.0.1:8000

| 项目 | 内容 |
|:-----|:----|
| **结论** | 🔴 **是 — 严重风险** |
| **严重性** | HIGH |
| **源码证据** | `src/lib/stampBackendApi.ts:3-4` |

```typescript
const BASE_URL =
  (import.meta.env.VITE_STAMP_BACKEND_URL as string | undefined) ?? 'http://127.0.0.1:8000';
```

**分析**:
- 项目中**不存在** `.env` 文件（已确认 `search_files('.env*')` → 0 results）
- 生产构建 (`npm run build`) 时 `VITE_STAMP_BACKEND_URL` 未定义 → fallback 到 `'http://127.0.0.1:8000'`
- Vite 的 `import.meta.env.*` 变量在构建时**静态替换**为字面量。未设置则替换为 fallback 值
- 生产环境中，前端 JS 在**用户浏览器**中运行，`127.0.0.1:8000` 指向**用户本机**，而非服务器
- 后果：**所有 STAMP Demo 请求在生产环境失败**，用户点击按钮后只能看到 "STAMP backend is not available" 错误

**修复方案** (二选一):
- **方案 A (推荐)**: 将 fallback 改为同源相对路径 `'/api/v1'`，依赖 Nginx 反向代理
  ```typescript
  const BASE_URL = (import.meta.env.VITE_STAMP_BACKEND_URL as string | undefined) ?? '/api/v1';
  ```
- **方案 B**: 创建 `.env.production` 文件，设置 `VITE_STAMP_BACKEND_URL=https://peptide.example.com/api/v1`

> ⚠️ 方案 A 还需同步修改 `apiFetch()` 中 `fetch(\`${BASE_URL}${path}\`)` → `fetch(\`${BASE_URL}${path}\`)`。如果 BASE_URL 为 `'/api/v1'`，则拼接后为 `'/api/v1/api/v1/stamp/demo-one'`，需将 path 参数从 `/api/v1/stamp/demo-one` 改为 `/stamp/demo-one`。

### R2 — 是否改为线上同源 /api/v1

| 项目 | 内容 |
|:-----|:----|
| **结论** | 🔴 **否 — 严重风险** |
| **严重性** | HIGH |
| **源码证据** | `stampBackendApi.ts:3-4`, `stampBackendApi.ts:11` |

**分析**:
- API 路径硬编码为 `fetch(\`${BASE_URL}${path}\`)`，其中 `path` 传入 `/api/v1/stamp/demo-one`
- 当前 fallback URL 为 `http://127.0.0.1:8000`，拼接后 `http://127.0.0.1:8000/api/v1/stamp/demo-one` — 这在**开发环境**可用（后端直连或 Vite proxy）
- 生产环境**不经过** Vite dev server，proxy 不生效
- 如果改为同源路径方案，需仔细处理路径拼接避免重复 `/api/v1/api/v1/...`

**修复方案**:
- 将 `apiFetch('/api/v1/stamp/demo-one')` 改为 `apiFetch('/stamp/demo-one')`
- 将 BASE_URL 改为 `'/api/v1'`
- 或者保持 path 不变，BASE_URL 改为 `''`（空字符串），依赖 nginx 做 `/api/v1` → 后端转发

### R3 — Nginx 是否需要增加 /api/v1 代理

| 项目 | 内容 |
|:-----|:----|
| **结论** | 🔴 **是 — 严重风险** |
| **严重性** | HIGH |
| **源码证据** | `release/v0.6c/DEPLOY_SERVER_V0.6C.md:36-56` |

**v0.6c Nginx 配置（纯静态文件服务器）**:
```nginx
server {
    listen 80;
    server_name peptide.example.com;
    root /opt/peptide-app/current;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /data/ {
        expires 1h;
        add_header Cache-Control "public, immutable";
    }

    location /structures/ {
        expires 1d;
        add_header Cache-Control "public, immutable";
    }
}
```

**分析**:
- v0.6c 是**纯静态前端部署**，无后端
- v0.6d 引入 FastAPI 后端（端口 8000），需要 Nginx 反向代理 `/api/` 路径
- 现有 Nginx 配置**没有任何 `/api/` 代理规则**
- 如果不添加代理，浏览器请求 `/api/v1/stamp/demo-one` 会被 `try_files` 捕获，返回 `index.html`（SPA fallback），导致 API 调用返回 HTML 而非 JSON

**修复方案** (必须添加到 Nginx 配置中):
```nginx
# STAMP Backend API proxy (v0.6d+)
location /api/ {
    proxy_pass http://127.0.0.1:8000;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 60s;
}
```
